# 1. 한 줄

M1 사이클의 UX 결함 6건(UX-1~6, M1 `08_improve.md`)을 해결한다. Light 테마 + 디자인 언어 재정의 + 복권 구매/뜯기 메커닉 + 상품 이미지 + 게이지/아코디언 + Last One 시각 강조.

# 2. 스코프 (in scope)

## 2.1. 디자인 언어 (UX-1, UX-2)

2.1.1. **Light 테마**: 흰 배경 / 짙은 텍스트 / 채도 낮은 액센트. tokens.css 전면 재작성.
2.1.2. **디자인 언어**: 클로드코드 풍 회피. 일본 쿠지 매장의 종이 / 카드 톤(따뜻한 베이지 / 크림 / 골드 강조). 둥근 카드 + 그림자 + 종이 텍스처(선택).
2.1.3. **타이포그래피**: 한국어 가독성 우선 + 일본어 원어 보조 (Noto Sans KR / Noto Serif JP 페어).
2.1.4. **버튼 / 상호작용**: 햅틱 적합 큰 터치 영역, 명확한 hover / active 상태.

## 2.2. 하단 탭 SVG 아이콘 (UX-3)

2.2.1. 4개 탭 (추첨 / 전적 / DC / 설정) 각각 SVG 아이콘 추가.
2.2.2. 아이콘은 자비스가 SVG path 직접 작성 (외부 lib 불요).
2.2.3. 활성 / 비활성 상태 색 구분.

## 2.3. 복권 구매 씬 (UX-4)

2.3.1. 추첨 탭의 첫 화면을 "복권 구매" 씬으로 변경.
2.3.2. 구매 옵션:
- Quick 버튼: **1장 / 3장 / 10장** (3개)
- 자유 입력: 1 ~ 박스 잔여 매수 사이 임의 정수
2.3.3. 가격 합산 표시: `n매 × LINEUP_PRICE_JPY = 합계엔`.
2.3.4. 박스 잔여 ≥ 구매 매수 검증. 부족 시 buy 비활성 + 안내.
2.3.5. 구매 완료 시 "지갑 / 인벤토리"에 미개봉 복권 N매 추가 → "뜯기" 화면으로 자동 전환.

## 2.4. 복권 뜯기 UI (UX-4)

2.4.1. 미개봉 복권 N매가 손패 형태로 표시 (스택 또는 펼침).
2.4.2. 한 장 선택 → 뜯기 애니메이션 (실제 이찌방쿠지 복권 폼 모방).
2.4.3. **두겹 구조**: 외부 면(IP 디자인 + 봉인 표시) → 뜯으면 내부 면(등급 + 상품).
2.4.4. 단계 2 design에서 실제 일본 이찌방쿠지 복권 폼을 WebSearch 조사 후 폼 결정.
2.4.5. 뜯은 복권은 (a) 결과 모달에 큰 화면 표시 후 (b) 해당 등급 상품 위에 오버레이로 부착.
2.4.6. 미개봉 복권이 0매가 되면 "구매 씬"으로 자동 복귀.

## 2.5. 상품 갤러리 + 오버레이 (UX-5)

2.5.1. 등급별 잔여 표시를 "상품 갤러리" 형태로 재설계.
2.5.2. 각 등급 항목:
- **상품 실물 이미지**: 자비스 SVG 자체 제작. 손오공 / 부르마 / 초사이어인 등 캐릭터별 단순 일러스트.
- **뜯은 복권 오버레이**: 박스에서 이미 뽑힌 분량만큼 복권 1장씩 상품 위에 부착 (시각적 적층).
- **딤드 처리**: 1매 등급(A~F, Last One)에서 뽑힌 경우 상품 이미지 회색 + 복권 1장 부착.
- **게이지**: 다수 등급(G 8 / H 8 / I 24 / J 33)은 잔여/총 매수 게이지 바.
- **아코디언**: 등급 헤더 클릭 시 종 수 ≥ 2 등급의 종별 상세(8종 / 10종) 펼침.
2.5.3. 종별 이미지: 종 수 ≥ 2 등급은 종 인덱스별 단순 일러스트(8종 / 10종 모두 별도 SVG).

## 2.6. Last One 시각 강조 (UX-6)

2.6.1. 박스 잔여 쿠폰 = 1매 시점에 화면 상단에 **눈에 띄는 인디케이터** (펄스 / 카운트다운 톤).
2.6.2. Last One 상품 이미지가 골드 테두리 + 발광 효과.
2.6.3. 마지막 1매 추첨 시 풀스크린 모달 (마지막 카드 + Last One 동시 표시) - M1 last-one-modal 강화.

## 2.7. 자료 / 데이터

2.7.1. 상품 이미지 자산 위치: `src/assets/products/<tier>-<typeIndex>.svg` 또는 인라인 SVG (라이선스 0 보장).
2.7.2. 02_data 신설 절: `1.6. 상품 이미지 자산` (각 등급 / 종 인덱스별 자산 ID 매핑).

## 2.8. 운영 학습 반영 (M1 OP-1~4)

2.8.1. **OP-2** (시그니처 변경 시 replace_all + grep): M2 단계 5 시 적용.
2.8.2. **OP-3** (자체 grep 사전 검증): M2 단계 6 진입 전 자비스가 매직 넘버 / 시그니처 호출처 grep 셀프 검증.
2.8.3. **OP-4** (tests/ 매직 넘버 검증): M2 단계 6 게이트에 `tests/` 매직 넘버 검사 명시.

# 4. 성공 기준 (acceptance criteria)

4.1. 사용자가 모바일 웹에서 박스 진입 → 1/3/10/자유 매수 복권 구매 → 한 장씩 뜯기 → 등급 / 상품 확인 → 박스 종료(잔여 0)까지 자연스럽게 진행.
4.2. Light 테마 + 클로드코드 풍 톤 0건 (다크 배경 / mono 폰트 위주 0건).
4.3. 하단 탭 4개 모두 SVG 아이콘 + 활성 / 비활성 상태 구분.
4.4. 복권 뜯기 UI가 두겹 구조 (외부 면 → 내부 면) 애니메이션 동작.
4.5. 상품 갤러리에서 1매 등급 7개(A~F + Last One)가 뽑히면 딤드 + 복권 1장 오버레이 표시.
4.6. 다수 등급 4개(G 8 / H 8 / I 24 / J 33)에 게이지 바 + 아코디언 펼침 시 종별 일러스트.
4.7. 박스 잔여 1매 시점에 Last One 인디케이터 + 골드 테두리 강조.
4.8. M1 검증 룰 100% 유지: 매직 넘버 0개 (src/ + tests/), core/ DOM import 0개, 결정론, 사행성 표현 0건.
4.9. 모든 신규 메커닉(구매 / 뜯기 / 게이지 / 아코디언)에 단위 테스트 추가.
